# 参考图与卡片需求

只做需求分析，不含实现。结论应用前需走 cs-epic 契约变更：更新永久文档、重新评审、主人重新确认。

## 一、需求结论

1. 档案需要新增一层「参考图」：人物身份、服装状态、场景卡各带一张主人确认过的图，风格 ID 带一张风格样张。
2. 三视图不是必需产物。必需的是**一张正脸参考图**。侧视、背视可选，且必须从已确认的正脸派生，不能一次生成三视图拼版。
3. 参考图的生成与确认放在 **ITEM-2**，不放 ITEM-1。ITEM-1 保持纯文字抽取、离线可测、无图片供应商依赖。
4. **物品卡 v1 不加。** 记下触发条件，留给中篇、长篇。
5. 场景的时间与光照变体、群体人物、地区建筑体系，v1 都不做。

## 二、依据：契约现在自相矛盾

- ITEM-4 设计约束写着「出图使用可替换的参考图接口，身份、当前服装、场景分开传入」。
- 遗留风险写着「参考图不能保证像素级同一张脸」。
- 但四个子项里，没有任何一个产出参考图。档案三块加风格 ID，全是文字。

也就是说：ITEM-4 声称要「分开传入」的四样东西，今天只有文字可传。「参考图接口」这个说法没有输入来源。

## 三、三方案对比

| 做法 | 对 ITEM-4 的影响 | 优点 | 缺点 | 前置条件 |
|---|---|---|---|---|
| A 不生成参考图，纯文字 | 每页独立解释同一句外貌，逐页漂移；ITEM-4 的「参考图接口」名存实亡，须改写契约 | 调用最少、最便宜、无新产物、ITEM-1/2 都不动 | 一致性没有任何锚点；主人确认的是句子不是脸，确认关卡对「样貌一致」基本失效；局部重画算得准命中页，但重画出来的还是新随机脸 | 无（但要改 ITEM-4 契约） |
| B 生成正脸参考图 | 身份、服装、场景各传一张已确认的图，锚点固定；局部重画的验收才有意义 | 契约本来就要求；主人确认的是真图；换页不换脸 | 多几次出图调用；参考图本身可能画不好，需要重画循环；需要图片供应商接口与存放位置 | 图片供应商接口；参考图存放；能在本地看图（本地文件即可，不需要网站） |
| C 一次生成三视图拼版 | 多角度锚点，理论上最强 | 长篇最稳 | 一次生成的三视图内部常常不是同一个人，前脸和背脸像两个人；锚错了比没锚更糟；主人审核成本翻倍；短篇收益低 | 同 B，外加「三视图内部一致」这个本身没有保证的东西 |

结论：v1 取 B；不取 A（契约冲突且一致性失效）；不把 C 当必需（风险收益比差）。

## 四、建议

1. 新增共享语言术语 **参考图**：挂在档案项上、经主人确认的图像锚点。
   - 不包括：页图、分镜草稿、未确认的试画。
   - 关系 / 不变量：出页时作为该档案项的参考输入传入；缺参考图等同该项未确认。
   - 来源：ITEM-2。
2. 人物身份：必需一张正脸参考图。
3. 服装状态：被 2 页以上引用时必需一张参考图（该人物穿这套衣服的样子，不是孤立的一件衣服）。
4. 场景卡：被 2 页以上引用时必需一张参考图（建筑外观）。
5. 风格 ID：必需一张风格样张（一页样例）。风格管全篇每一页，所以是必需项。
6. 参考图有两条来源，都接受：工具用档案文字做提示词生成；或主人自己放一张图进去。
7. 三视图：v1 可选，且必须从已确认的正脸用图生图派生。
8. 引用记录不变，仍是四类 ID。2 页规则在 ITEM-4 入口按引用记录判定。

第 3、4 条为什么用「2 页以上」而不是「一律必需」：只出现一次的服装或场景没有漂移风险，强制出图只是增加主人的审核负担。规则挂在实际风险上。

## 五、人物身份字段偏薄（参考图的前置）

现在人物身份只有脸、年龄、体态。这个厚度不足以生成一张能锚住人的正脸图。建议最少补到：

- 脸型（把现在的「脸」拆开）
- 发型与发色
- 眼（眼型与瞳色）
- 显著特征（疤、痣、眼镜等）
- 年龄
- 体态

不继续扩张成完整人设表。这是共享语言里人物身份定义的契约变化。

## 六、物品卡与其他卡

**物品卡**：v1 不加。需要它要同时满足三条：反复出现、读者靠它认情节、容易漂移。1 到 2 万字短篇里，多数道具只出现一两次，且不承载识别功能。加它还要给引用记录加第五类 ID，ITEM-3 与 ITEM-4 都要改契约，验收也要多一条。收益低。
触发条件：某物品被 3 页以上引用且承载情节识别时，中篇或长篇再引入。

**场景的时间与光照变体**：与服装状态对称（地点身份 + 光照状态）。v1 不做状态机，光照作为页级提示词修饰，不改参考图。

**地区与建筑风格卡**：非目标已排除（不建完整地理数据库）。场景卡里的「建筑外观」就是 v1 的落点。

**群体与背景人物卡**：v1 不做。背景人物允许变化。

**风格卡**：由风格 ID 升级为带样张的风格卡。要做，见建议 5。

## 七、与各子项的关系

- **ITEM-1**：仍只产出文字草稿，不产参考图。但人物身份字段需要加厚（第五节）。契约其余不变。
- **ITEM-2**：本轮最大的契约变化。确认对象从「文字」变成「文字 + 参考图」；改文字会使对应参考图退回未确认；支持主人自带图。
- **ITEM-3**：引用记录不变，页剧本仍不写外貌。不需要新契约。
- **ITEM-4**：入口按引用记录执行 2 页规则，缺参考图则拒绝出页；参考输入取自已确认参考图。

## 八、待应用到 Epic 的契约增量

1. 共享语言新增「参考图」术语。
2. 人物身份字段加厚（第五节）。
3. 档案定义补一句：三块与风格 ID 各自可带一张参考图。
4. ITEM-2 增补：生成或接收参考图，并纳入确认；改文字使参考图退回未确认。
5. ITEM-4 增补：按 2 页规则检查参考图，缺失即拒绝出页。
6. 非目标或遗留风险增补：v1 不含物品卡，触发条件如上。
7. 遗留风险那条「参考图不能保证像素级同一张脸」保留，现在它有了对应的产物。

## 九、主人已记录的选择

2026-10-15 逐项选定，作为第八节契约增量的执行口径。

1. **参考图**：加。人物身份带一张正脸参考图。
2. **三视图**：完全不做，侧视和背视也不做。人物参考图只保留一张正脸。
3. **服装状态与场景卡的参考图门槛**：被 2 页以上引用时才必需。只被 1 页引用时不要求。
4. **物品卡**：v1 不加。触发条件为某物品被 3 页以上引用且承载情节识别，中篇或长篇再引入。
5. **人物身份字段**：加厚为脸型、发型与发色、眼（眼型与瞳色）、显著特征、年龄、体态。
6. **参考图来源**：两条都接受。工具依档案文字生成，或主人自带一张图替代。
7. **落地方式**：走契约变更。更新永久文档 → fresh reviewer 契约评审 → 主人重新确认 → 替换批准指纹 → 重做 ITEM-1 与 ITEM-2。

与建议的差异：第 2 条比建议更严，建议原本把三视图列为可选，主人选择完全不做。
